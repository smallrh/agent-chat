## 去重与冲突收敛（同槽位多版本只注入最新）
问题：现有 merge 只去重"完全相同的语义事实"，对"属性更新"（Java→Go、北京→深圳、Windows→macOS）
会判为不同事实 → 两条都 active → 注入时出现新旧矛盾。引入 `slot`（属性槽位）概念收敛。
改动文件：
- `public.sql`：memories 新增 `slot varchar(50)` + 索引 `memories_user_slot_idx(user_id, slot)`。
  （注意：运行库需执行对应 ALTER/CREATE INDEX，否则 save 的 INSERT 会报缺列）
- `app/core/config.py`：新增 `MEMORY_CONVERGE_BY_SLOT=True`（开关）。
- `app/repo/memory_repo.py`：save 写入 slot；get_by_id/get_by_ids/list_memories 返回 slot。
- `app/repo/qdrant_repo.py`：upsert payload 增加可选 slot。
- `app/kafka/memory_worker.py`：抽取 prompt 要求 LLM 输出 slot（同属性不同取值共用 key，给了
  Java/Go→primary_language、北京/深圳→residence_city、Windows/macOS→os 三组示例）；
  _parse_memory_json 解析 slot（缺失回退 memory_type）；save 的 upsert 透传 slot。
- `app/service/retrieval_service.py`：新增 `_converge_by_slot`（同 slot 只留 created_at 最新；
  无 slot 老数据按 memory_id 独立保留）；retrieve 在组装结果后按开关收敛；结果 dict 增加 slot 字段。
- `app/service/memory_service.py`：update_memory 新版本继承旧版本 slot（同槽位收敛）。
- `app/api/memory.py`：MemoryItem 增加 slot 字段（记忆检视 API）。

验证：py_compile 通过；_converge_by_slot + 完整 retrieve 收敛单测通过（Java/北京/Windows 被丢弃，
保留 Go/深圳/macOS；无 slot 的"火锅"独立保留；开关关闭时不过滤）。
设计要点：收敛放在读取端（retrieve）单一位置，任何消费方都拿到已收敛结果；写入端保留 slot 供未来
写时合并参考。

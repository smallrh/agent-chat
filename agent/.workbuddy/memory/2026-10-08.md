## Go Agent Proxy SSE 流式透传修复（backend/internal/router/router.go）
- 问题：Go 外壳（:8080）的 `/agent/*` 反向代理用 `io.Copy(c.Writer, resp.Body)` 透传，但 gin 的写缓冲（默认 4096B）不会自动 Flush，导致 Python `/chat/stream`（SSE）事件被攒批，客户端收流卡顿。
- 修复：新增 `flushWriter`（包装 http.ResponseWriter，每次 Write 后调 http.Flusher.Flush）+ `isStreamingResponse()`；仅当 `Content-Type` 含 `text/event-stream` 时走 flushWriter，普通 JSON 仍直连 io.Copy。
- 验证：go build ./... 通过（EXIT=0）。go vet 在本 Windows 沙箱无输出退出1（疑似环境对 vet 临时编译的限制，非代码问题），未跑依赖 PG/Redis 的集成测试。
- 备注：隐患#2（注册链路 EnsureUser）经核实已在 auth_service.go:104 调用 pythonUserRepo.EnsureUser，落库链路本就打通，无需改。

## 前端 React 应用从零搭建（frontend/，技术栈 Vite+React+TS+Tailwind）
- 背景：原仓库前端目录为空（完成度评估 0%）。用户要求实现登录/注册/登出/对话的前端展示。经确认技术栈用 Vite+React+TS+Tailwind。
- 对接契约（已读 backend 源码核实）：Auth 走 Go Auth(:8080) `/api/v1/auth/{register,login,refresh,logout,me}`，统一响应 `{code,message,data,request_id}`；对话经 Go 代理 `/agent/chat`（非流式）、`/agent/chat/stream`（SSE）。token=Bearer，refresh 用 refresh_token 轮转。
- 关键实现：
  - `src/api/client.ts`：fetch 封装 + 统一响应解析 + 401 自动 refresh 重试 + 刷新失败派发 `auth:unauthorized` 事件（AuthContext 监听后清登出）。
  - `src/api/chat.ts`：`streamChat` 用 fetch+ReadableStream 手动解析 SSE（事件块 `\n\n` 分隔，data 为 JSON），逐事件 yield（`agent.start` 取 conversation_id、`message.delta` 累积 content、`done` 收尾、`error` 标红）。
  - `src/auth/AuthContext.tsx`：用户态 + login/logout + 启动用 /me 恢复 + 监听 unauthorized 事件。
  - 页面：Login/Register（注册后自动 login）/Chat（流式打字+新对话+会话 id 续聊）。
  - `vite.config.ts`：dev server 代理 `/api`、`/agent` → `http://127.0.0.1:8080`，规避 CORS。
- 验证：npm install 成功（137 包）；`npm run build`（tsc + vite build）通过，dist/ 产出 JS 57.6kB gzip。

## 问题：GET /memories 对 user_id=1 返回空 + Qdrant 报不可达

### 根因
1. **EMBEDDING_BASE_URL 配置错误（核心 bug）**
   - `config.py` 默认 `EMBEDDING_BASE_URL = "http://127.0.0.1:1234/v1/embeddings"`
   - OpenAI SDK 会在 base_url 后自动拼 `/embeddings` → 实际请求 `.../v1/embeddings/embeddings` → LM Studio 返回空 → `embed()` 抛异常 → 每条记忆 `mark_pending_failed`，全部卡 `pending` 永不 `indexed`。
   - 修正为 `http://127.0.0.1:1234/v1` 后实测正常（dim=768）。

2. **Qdrant 启动竞态（非致命化缺失）**
   - `QdrantRepository.start()` 启动期连不上就把 `client` 置 None 且永不重试 → 整个进程期 Qdrant 被静默跳过。
   - 已加 `_ensure_client()` 惰性重连（带 asyncio.Lock 双重检查）。

3. **user_id=1 的 4 条记忆全部 is_active=false**
   - PATCH 版本化测试残留：`用户的名字是 Alice`/`用户喜欢吃火锅`（原始，被标记非活跃）+ 两条 `已更新的记忆内容（测试版本化）` 占位行。
   - 用户选择「4 条全部激活」→ 已 UPDATE is_active=true。

## 08:02 Qdrant「连不上」复检：并非硬 bug，是韧性缺口 + 双实例

### 用户现象
- 启动日志报 `QdrantRepository.start: Qdrant not reachable at 127.0.0.1:6333`（07:50:58），用户坚称 Qdrant 可连、是代码问题。

### 实测排除硬 bug
- Qdrant REST 6333 实测 LIVE：`HTTP 200 / status=green / points_count=5`。
- 用真实 `QdrantRepository` 类在独立 event loop 跑 `start()`+`_ensure_client()` → 全部成功连上（qdrant-client 1.19.1，`prefer_grpc` 默认 `False`，**非 gRPC 问题**）。
- 代理变量 `HTTP_PROXY/HTTPS_PROXY=127.0.0.1:7897`，`NO_PROXY=localhost,127.0.0.1,::1` → 127.0.0.1 请求绕过代理，不影响连接。

### 真正根因（两个）
1. **韧性缺口**：`start()` 启动期只试一次；空闲（无新记忆写入、reconcile 扫到 0 pending）时没有任何操作触发 `_ensure_client`，连接永久停在 `None` → 表现「一直连不上」。
2. **QdrantRepository 在 3-4 处各自 `QdrantRepository()` 独立实例化**（memory_worker / reconcile_consumer / MemoryCRUDService / 传入 MemoryService），每实例各自连、各自卡 None。
3. **双实例**：端口 1111 同时跑着两个 app——项目 `.venv`（23424，我后台起的）+ conda `py3147`（27480，用户约 07:50 手动起的，正是告警来源）。两 env 的 qdrant-client 实际都是 1.19.1（非版本差异），但双实例本身会让请求被分发到连接已假死的那个。

### 修复（已全部重启验证通过）
- `app/repo/qdrant_repo.py`：
  - 新增 `get_qdrant_repo()` 进程内单例（消除多实例各连各的）。
  - `start()` 改为启动重试 `QDRANT_STARTUP_MAX_RETRIES`(=3) × `QDRANT_STARTUP_RETRY_INTERVAL`(=1.5s) + `_started` 防重复。
  - 新增 `ensure_connected()`：已有 client 做轻量 liveness（`get_collections`），断了就关掉下轮重连；被所有 Qdrant 操作与后台健康循环共用。`_connect()` 显式 `prefer_grpc=False` 并关闭旧 client（防泄漏）。
- `app/core/config.py`：新增 `QDRANT_STARTUP_MAX_RETRIES=3`、`QDRANT_STARTUP_RETRY_INTERVAL=1.5`、`QDRANT_HEALTH_INTERVAL_SECONDS=15`。
- `app/main.py`：新增后台 `_qdrant_health_loop()`（每 15s `ensure_connected()`，覆盖「Qdrant 中途重启/一直没连上」且空闲也重连），lifespan 启动 + 关闭时 cancel。
- 调用点 `memory_worker.py` / `reconcile_consumer.py` / `memory_service.py(MemoryCRUDService)` 的 `QdrantRepository()` → `get_qdrant_repo()`。
- 验证：杀掉双实例后仅用 `.venv` 重启；日志 `QdrantRepository started (127.0.0.1:6333) on attempt 1/3` + `qdrant health loop started (every 15s) ✅`，**无 not reachable 告警**；GET /memories(uid=1)→2 条真实记忆 indexed；Qdrant LTM=5 green。

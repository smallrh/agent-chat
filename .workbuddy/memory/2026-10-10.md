## P2：真任务队列（后台 worker）+ 附件/多模态（续）

在 P0/P1 六项之后继续做 `docs/优化记录.md` 里的第 7、8 项，两侧均已写台账。

### P2-1 真任务队列
- 关键设计：**协作式取消**。真实 worker 的耗时在 `web_search` 的同步 httpx 里（跑在 `to_thread`，`asyncio` 取消打不断），所以 `cancel_task()` 必须**先置 `TaskCancelToken` 再 `Task.cancel()`**，handler 在每个子步 `raise_if_cancelled()`。
- 踩坑：`_finalize()` 里若把 `CancelledError` 继续往外抛，`task.cancelled` 事件就发不出去、前端永远转圈。现已改为用 `asyncio.shield` 包终态写入并**吞掉**取消。
- 另一个坑：handler 跑完前用户已取消（DB 已是 cancelled）时不能覆盖回 succeeded —— 已加「终态前重读 DB」的竞态保护。
- tasks 表加 `kind/step/steps_done/steps_total`（V011）；`kind` 此前 API 收了但没列存，落库即丢。
- SSE 加 30s `: ping` 心跳，防长任务期间被反向代理掐断；前端 `api/sse.ts` 统一忽略注释行。
- `create_task` 工具默认 `kind` 由 `demo` 改为 `research`（模型默认建的就是真调研任务）。
- 并发上限：`TASK_MAX_ACTIVE_PER_USER=3` / `TASK_MAX_ACTIVE_GLOBAL=20`，超限 429。
- 自检脚本 `agent/_test_p2_tasks.py`（假 repo，不依赖 PG/外网）覆盖 5 个场景，全部通过。

### P2-2 附件与多模态
- 文件**不入库**，落 `ATTACHMENT_DIR/<user_id>/<attachment_id><ext>`，DB 只存 storage_path + 抽取文本；文件名用 attachment_id（防路径穿越 + 防同名覆盖）。
- `agent.py::_build_messages` 有图片时 user content 从字符串变 **content part 数组**（vision 必需）。
- 新增依赖 `pypdf`（已写入 `agent/requirements.txt` 并装进 .venv）；未安装时降级为「未能抽取」而非空串。
- Go BFF：上传走 `BFFProxy.JSON`（透传 multipart Content-Type，boundary 不破坏）；下载走新增的 `BFFProxy.Raw()` **二进制原样透传**（套信封会让 `<img src>` 失效）。
- 前端上传**不能**用统一 `request()`（它强写 `application/json` 会毁掉 boundary），用自定义 fetch。
- gin 路由：`/tasks/kinds`、`/tasks/stream` 必须声明在 `/tasks/:id` 之前（已实测 gin 支持静态段与参数段共存，不 panic）。

### 本轮新确立的约定
- 新增任务类型只改 `agent/app/service/task_worker.py`（`register_default_handlers`），TaskService 只认 kind 字符串。
- 前端 SSE 解析统一走 `src/api/sse.ts`，不要再手写第二份。
- gin 静态子路径必须先于 `/:id` 声明（虽然 gin 不 panic，但可读性/可维护性要求）。

## P3（续）：评测集 + 计费配额（组织账号暂缓）

用户确认范围：P3 拆成「评测集 + 计费配额」两项做，**组织账号暂缓**
（要重写会话/记忆/任务的 `user_id` 归属校验，回归面远大于另两项，单独排期）。

### 评测集 `agent/evals/`
- 两层：`offline`（不调模型，19 条确定性断言，0.4s，CI 可跑）+ `online`
  （黄金问答 8 条，需 LM Studio；**模型不可达时整层跳过、不计失败**，
  否则 CI 上没开 LM Studio 就误报一片红，很快没人看评测）。
- 用法 `./.venv/Scripts/python.exe -m evals.runner [--layer all] [--case xxx]`。
- 反编造是**条件断言**不是关键词断言：检索 failed/empty → 必须有降级话术；
  检索 ok → 引用的 URL 必须在工具原文里。写「不许出现地址」是错的（检索成功时给地址是正确行为）。
- 踩坑1：`evals/__init__.py` 里 `from .runner import main` 会让 `python -m evals.runner`
  报 "found in sys.modules after import of package"、行为不可预期 → `__init__` 保持空。
- 踩坑2：第一版两条红**都是用例写错**，不是产品缺陷：①降级话术原文是
  「未经外部来源核实」，不含连续子串「未核实」；②`search_cache.get()` 按设计
  **只返回精确命中**，相似命中要用 `get_with_meta()` 看 kind（线上 web_search 用的正是后者）。
- 实测 27 条全过；hotel-1 回答「无法给出确定的评分最高的酒店…口径不一致」+ 带来源候选表，
  说明 grounding 确实生效。

### 计费 / 配额
- 架构：**Agent 写 Redis 计数、Go 读 + 拦截**。拦截必须在 Go（请求进 Agent 之前），
  计数必须在 Agent（只有它知道这轮搜了几次、有没有真实产出）。
- key 规则两端必须一致：`usage:{metric}:{user_id}:{YYYYMMDD}` /
  `usage:m:{metric}:{user_id}:{YYYYMM}`（已用临时 Go 探针验证跨端读到同一个值）。
- 计量：chat（轮次）/ web_search（检索次数）/ task（任务数）。埋点放在**本轮结束**
  （失败/取消不计费）。Redis 故障一律放行 —— 计费挂了不能让用户聊不了天。
- Go 侧：`user_plans` 表（0005 迁移；无记录 = 用 config 默认套餐）+ `QuotaService` +
  `QuotaMiddleware` + `/api/v1/usage/me` + admin 端点（`X-Admin-Token`，
  留空则 **404 而非 401**，连「存在管理接口」都不暴露）。
- **router.New 改用 functional options**（`router.WithDatabase(...)`）：不注入 database
  时计费路由整体不注册，集成测试零改动。以后新增依赖 DB 的路由都照这个模式加，
  不要再给 `New()` 加必填参数。
- 配额 `0 = 不限`，判定必须先判 `limit > 0`，否则「不限」的用户第 0 次就被拦。
- 与限流分工：ChatGuard 管瞬时（防打爆连接池），Quota 管总量（计费）。两者都要有。

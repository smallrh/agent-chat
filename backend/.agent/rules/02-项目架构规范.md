# 项目架构规范

## 1. 基础分层

推荐：

Handler
↓
Service
↓
Repository
↓
PostgreSQL

外部服务：

Service
↓
Client
↓
External Service

---

## 2. Handler

Handler 只负责：

- HTTP 参数解析
- 参数校验
- 调用 Service
- HTTP Response

Handler 不允许：

- 直接写 SQL
- 直接操作 Redis
- 直接生成 JWT
- 直接验证密码
- 直接调用 Agent
- 编写复杂业务逻辑

---

## 3. Service

Service 负责业务逻辑。

例如：

- Register
- Login
- Refresh
- Logout
- 验证密码
- Token Rotation

Service 不应该依赖 Gin Context。

推荐：

func (s *AuthService) Login(
ctx context.Context,
username string,
password string,
) (*TokenPair, error)

---

## 4. Repository

Repository 只负责数据访问：

- SELECT
- INSERT
- UPDATE
- DELETE
- Transaction

Repository 不负责：

- JWT
- 密码验证
- HTTP Status
- HTTP Header
- Agent 业务

---

## 5. Client

所有外部服务都应该通过 Client 封装。

例如：

internal/client/agent_client.go

禁止 Handler 直接：

http.Post(...)
http.Get(...)

---

## 6. 不要过度设计

禁止为了体现“架构”而增加：

- 无意义 Factory
- 无意义 Interface
- 无意义 Manager
- 无意义 Provider
- 无意义 Event Bus
- 无意义 Dependency Injection Framework

优先使用简单、清晰的 Go 代码。

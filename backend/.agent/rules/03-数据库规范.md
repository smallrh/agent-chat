# 数据库规范

## 1. 整体架构

本项目是**双服务共用同一个 PostgreSQL 数据库**的模式：

- **Go Auth Service** → 读写 `auth_users`、`refresh_tokens` 表
- **Python Agent** → 读写 `users`、`conversations`、`messages`、`memories` 表

两个服务共享同一个 database（agent_system），**但各自管理自己的表，禁止跨服务修改对方表的 Schema**。

```
agent_system (PostgreSQL)
├── auth_users         ← Go Auth 独占
├── refresh_tokens     ← Go Auth 独占
├── users              ← Python Agent 独占
├── conversations      ← Python Agent 独占
├── messages           ← Python Agent 独占
└── memories           ← Python Agent 独占
```

---

## 2. 两张用户表的关系

Go Auth 侧：

- `auth_users.auth_user_uuid` —— 跨服务身份标识（UUID）
- 负责登录、密码、JWT

Python Agent 侧：

- `users.user_uuid` —— 跨服务身份标识（UUID）
- 负责业务数据关联（conversations、messages、memories）

**关联关系**：`auth_users.auth_user_uuid = users.user_uuid`

Go Auth 的 [python_user_repo.go](file:///d:/work/agent_system/backend/internal/repository/python_user_repo.go) 会在注册时自动 `EnsureUser`，确保 Python 侧 `users` 表有对应记录。

## 4. SQL 参数化

必须使用参数化 SQL。

PostgreSQL 参数占位符：`$1, $2, ...`

Go 侧正确示例：

```go
const query = `
    SELECT id, auth_user_uuid, username, email, status, created_at, updated_at
    FROM auth_users
    WHERE username = $1
`
db.GetContext(ctx, &user, query, username)
```

Python 侧正确示例：

```python
sql = """
    SELECT id, conversation_id, user_id, title
    FROM conversations
    WHERE user_id = $1
"""
await conn.fetchrow(sql, user_id)
```

**禁止字符串拼接 SQL**。

---

## 5. 禁止 SELECT *

生产 SQL 必须明确字段列表。

禁止：

```sql
SELECT * FROM auth_users
```

应该：

```sql
SELECT id, auth_user_uuid, username, email, password_hash, status, created_at, updated_at
FROM auth_users
```

## 6. Go Auth 表结构

### auth_users（Go Auth 独占）

```sql
CREATE TABLE auth_users (
    id              BIGSERIAL PRIMARY KEY,
    auth_user_uuid  UUID NOT NULL UNIQUE,
    username        VARCHAR(128) NOT NULL UNIQUE,
    email           VARCHAR(256) NOT NULL UNIQUE,
    password_hash   VARCHAR(256) NOT NULL,
    status          SMALLINT NOT NULL DEFAULT 1,  -- 1=active, 2=disabled
    created_at      TIMESTAMPTZ(6) NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ(6) NOT NULL DEFAULT NOW()
);
```

### refresh_tokens（Go Auth 独占）

```sql
CREATE TABLE refresh_tokens (
    id                BIGSERIAL PRIMARY KEY,
    auth_user_id      BIGINT NOT NULL REFERENCES auth_users(id) ON DELETE CASCADE,
    token_hash        VARCHAR(256) NOT NULL UNIQUE,
    parent_token_id   BIGINT REFERENCES refresh_tokens(id) ON DELETE SET NULL,
    device_id         VARCHAR(128),
    user_agent        VARCHAR(512),
    expires_at        TIMESTAMPTZ(6) NOT NULL,
    revoked_at        TIMESTAMPTZ(6),
    created_at        TIMESTAMPTZ(6) NOT NULL DEFAULT NOW()
);
```

## 8. 身份规则（重点）

| 场景 | 使用字段 | 类型 | 说明 |
|------|----------|------|------|
| Go Auth 内部关联 | `auth_users.id` | int64 | 只在 auth_users/refresh_tokens 内用 |
| Python Agent 内部关联 | `users.id` | int8 | 只在 Python 各业务表内用 |
| **跨服务身份** | `user_uuid` | UUID 字符串 | Go 的 `auth_user_uuid` = Python 的 `user_uuid` |
| JWT.sub | `user_uuid` | UUID 字符串 | **绝对不能用** users.id 或 auth_users.id |
| X-User-Id Header | `user_uuid` | UUID 字符串 | Go → Python 传递 |

**禁止**：

- JWT.sub = auth_users.id
- JWT.sub = users.id
- X-User-Id = auth_users.id
- X-User-Id = users.id

---

## 9. 数据库约束

重要业务规则必须用数据库约束，不能只靠应用层判断。

必须有：

- `auth_users.auth_user_uuid UNIQUE`
- `auth_users.username UNIQUE`
- `auth_users.email UNIQUE`
- `users.user_uuid UNIQUE`
- `refresh_tokens.token_hash UNIQUE`
- `refresh_tokens.auth_user_id FOREIGN KEY → auth_users.id ON DELETE CASCADE`

## 10. Migration

### Go Auth 侧（backend/migrations/）

使用 4 位数补零命名：

```
0001_create_auth_users.up.sql
0001_create_auth_users.down.sql
0002_create_refresh_tokens.up.sql
0002_create_refresh_tokens.down.sql
```

禁止：

- 跳号
- 3 位数 / 不补零
- 手工修改生产数据库绕过 Migration

### Python Agent 侧（agent/）

Python Agent 目前没有使用 golang-migrate 类工具，SQL 文件放在 agent 根目录。

**任何对 Python Agent 表结构的修改必须使用版本化 SQL 文件**（见第 12 节）。

## 12. SQL 文件版本化规范（重要）

任何会被多人复用的 SQL 文件（DDL、索引、数据修复脚本），必须**双重版本化**：

### 文件名版本号

格式：`v<yyyyMMdd>_<序号>_<描述>.sql`

例如：

```
v20260926_01_create_indexes.sql
v20260926_02_fix_missing_users.sql
v20260930_01_add_conversation_title.sql
```

### 文件头变更日志

每个可复用 SQL 文件必须在顶部有变更头：

```sql
-- ============================================================
-- Name: v20260926_01_create_memories_indexes.sql
-- Target: memories, conversations
-- Version: 1.0
-- Date: 2026-09-26
-- Author: xxx
-- Change: 为 memories / conversations 表新增复合查询索引
-- Impact: 查询性能，无数据迁移
-- Rollback: DROP INDEX IF EXISTS xxx;
-- ============================================================
```

### 什么时候需要新版本

以下场景**必须产出新版本 SQL 文件**，禁止原地覆盖：

- 新增/删除索引
- 新增/删除表
- 新增/删除字段
- 修改字段类型 / 约束
- 数据修复脚本（UPDATE 修复脏数据等）
- 去重 / 迁移 / 初始化脚本

### 什么时候可以原地修改

- 纯注释调整
- 格式化
- 修复明显拼写错误（不影响执行）

### Python Agent 侧的特殊说明

`agent/public.sql` 是 Navicat dump 出来的全量建表脚本，作为**初始建表基准**存在。后续增量变更用版本化 SQL 文件追加，**不要覆盖 public.sql**。

## 13. Transaction

涉及多个必须原子完成的数据库操作时使用 Transaction。

### Go Auth 侧场景

Refresh Token Rotation：

```
旧 Token revoke + 新 Token 创建 → 同 Transaction
```

### Python Agent 侧场景

Memory Worker 写入 memories + 更新 messages.memory_status → 同 Transaction

---

## 14. 并发注册

两个请求同时注册相同 username：

数据库最终只能存在一个。

必须依赖 `UNIQUE(username)` 约束，并正确处理 duplicate key：

- Go 侧：检测 PostgreSQL `23505` 错误码 → 返回 `ErrUsernameTaken` → Handler 映射 `409 Conflict`
- **不能先 SELECT COUNT(*) 再 INSERT**（竞态窗口）

---

## 15. 双服务跨表操作

Go Auth 侧 [python_user_repo.go](file:///d:/work/agent_system/backend/internal/repository/python_user_repo.go) 在注册时会同时写：

1. `auth_users`（INSERT）
2. `users`（INSERT IF NOT EXISTS）

这两步**不在同一个 Transaction 里**（不同 Repository 管理）。设计决策：

- `auth_users` 写入失败 → 注册失败，不写 `users`
- `auth_users` 成功 + `users` 写入失败 → 注册成功（降级，仅打 WARN 日志），后续幂等补写

**禁止**：在 Go Auth 里对 Python Agent 表做除 `EnsureUser`（写入 user_uuid 基础记录）之外的操作。Python Agent 表的业务操作由 Python Agent 自己完成。

# AI 编码规范

## 1. 编码之前

AI 修改代码之前必须先检查：

- 项目目录
- go.mod
- Go 版本
- HTTP Framework
- 数据库访问方式
- Model
- Repository
- Service
- Handler
- Router
- Middleware
- Config
- Migration
- Docker
- 测试

禁止：

未扫描项目 → 直接重构。

---

## 2. 技术栈

如果当前项目已经使用：

Gin
Echo
Fiber
Chi
GORM
sqlx
ent

优先复用。

不要因为个人偏好替换技术栈。

---

## 3. 新增依赖

添加第三方库之前必须确认：

1. 标准库能否解决。
2. 项目是否已有类似依赖。
3. 当前 Go 版本是否兼容。
4. 是否稳定维护。
5. 是否真的有必要。

---

## 4. 修改原则

遵循：

扫描
↓
理解
↓
设计
↓
最小修改
↓
实现
↓
测试
↓
修复
↓
再次测试

禁止无理由重写整个项目。

---

## 5. 数据库修改

修改 Model 时必须检查：

- Migration
- Index
- Unique Constraint
- Foreign Key
- Transaction

禁止只修改 Go Struct，不修改数据库。

---

## 6. 安全

认证相关代码必须重点检查：

- JWT Signature
- JWT Algorithm
- JWT Issuer
- JWT Expiration
- JWT Subject
- Password Hash
- Refresh Token
- Token Rotation
- Token Replay
- X-User-Id
- Rate Limit

---

## 7. Python Agent

Python Agent 是独立服务。

禁止为了实现 Go Auth：

直接修改 Python Agent 业务代码。

除非发现明确的 API Contract 问题，否则优先修改 Go Auth。

---

## 8. 测试

完成修改后执行：

go fmt ./...
go vet ./...
go test ./...
go build ./...

如果失败：

1. 阅读真实错误。
2. 定位原因。
3. 修改代码。
4. 再次运行。

---

## 9. 禁止伪造测试

没有执行：

go test ./...

不得输出：

[PASS]

只能输出：

[NOT RUN]

---

## 10. 最终汇报

完成任务后必须说明：

### 项目分析

- Go 版本
- Framework
- DB
- DB Library
- Redis
- 项目结构

### 修改文件

Created:
- xxx

Modified:
- xxx

Deleted:
- xxx

### 数据库

- Migration
- Index
- Constraint

### API

- 新增
- 修改

### 安全

- JWT
- Password
- Refresh Token
- X-User-Id

### 测试

只报告实际执行结果。

### 未解决问题

明确列出剩余问题。

不要为了让任务看起来完成而隐藏失败。

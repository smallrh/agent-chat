# 认证安全规范

## 1. 密码

禁止：

- 明文密码
- MD5
- SHA1
- SHA256(password)

必须使用：

Argon2id

数据库只能保存：

password_hash

---

## 2. 密码日志

绝对禁止日志输出：

- password
- password_hash

---

## 3. JWT

Access Token 至少包含：

sub
iat
exp
iss

其中：

sub = user_uuid

禁止：

sub = users.id

---

## 4. JWT 验证

必须验证：

- Signature
- Algorithm
- Issuer
- Expiration
- Subject

不能动态信任 Token Header 中的 Algorithm。

禁止：

alg = none

---

## 5. JWT 密钥

禁止硬编码：

JWT Private Key
JWT Secret

应该从：

- 环境变量
- Secret 文件
- Secret Manager

读取。

---

## 6. Access Token

默认：

15 分钟

必须配置化：

ACCESS_TOKEN_TTL=15m

---

## 7. Refresh Token

Refresh Token 必须独立于 Access Token。

禁止：

Refresh Token = Access Token

数据库保存：

token_hash

不要保存明文 Refresh Token。

---

## 8. Refresh Token Rotation

刷新：

Token A
↓
Refresh
↓
Token B

刷新成功后：

Token A = revoked
Token B = valid

旧 Token A 再次使用：

Token Reuse Detected

可以进一步撤销整个 Token Family。

---

## 9. Disabled User

如果：

status = disabled

禁止：

登录
获取新的 Token
刷新 Token

具体策略按照项目统一规范实现。

---

## 10. 登录错误

不要区分：

用户不存在

密码错误

统一返回：

Invalid username or password

---

## 11. X-User-Id

客户端传入：

X-User-Id

绝对不可信。

例如：

Authorization = User A
X-User-Id = User B

Go 必须：

验证 User A JWT
↓
读取 JWT.sub
↓
得到 User A
↓
删除客户端 X-User-Id
↓
重新设置 X-User-Id = User A

---

## 12. 敏感信息

禁止日志输出：

- password
- password_hash
- access_token
- refresh_token
- 完整 JWT
- private_key
- database password
- Authorization Header
- Cookie

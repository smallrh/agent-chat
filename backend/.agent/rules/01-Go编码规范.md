# Go 编码规范

## 1. 格式化

所有 Go 代码必须执行：

go fmt ./...

或者：

gofmt

禁止提交未格式化代码。

---

## 2. 编译检查

完成修改后至少执行：

go fmt ./...
go vet ./...
go test ./...
go build ./...

没有实际执行，不得声称通过。

---

## 3. 命名

Package：

使用小写：

package auth
package repository
package middleware

禁止：

package auth_service
package AuthService

类型：

type AuthService struct {}
type UserRepository struct {}

函数：

func CreateUser()
func ValidateToken()

遵循 Go 官方命名风格。

---

## 4. Interface

不要为了“面向接口”而创建大量 Interface。

只有一个实现时，优先使用具体类型。

错误：

type UserServiceInterface interface {
CreateUser()
}

正确：

type UserService struct {}

只有确实需要抽象时才使用 Interface。

Interface 优先由使用方定义。

---

## 5. Context

涉及：

- PostgreSQL
- Redis
- HTTP
- 外部服务

的函数必须传递 context.Context。

正确：

func (r *UserRepository) FindByUsername(
ctx context.Context,
username string,
) (*User, error)

禁止在业务代码中随意：

context.Background()

必须沿调用链传递：

HTTP Request
↓
Handler
↓
Service
↓
Repository / Client

---

## 6. 错误处理

禁止忽略错误。

错误：

tx, _ := db.Begin()

正确：

tx, err := db.BeginTxx(ctx, nil)
if err != nil {
return err
}

---

## 7. Error Wrapping

需要增加上下文时：

fmt.Errorf("查询用户失败: %w", err)

保持错误链完整。

使用：

errors.Is()
errors.As()

进行错误判断。

---

## 8. Panic

业务代码禁止使用 panic。

错误：

if err != nil {
panic(err)
}

业务错误必须正常返回。

---

## 9. Goroutine

禁止无控制地创建后台 Goroutine。

必须考虑：

- 生命周期
- Context
- 取消
- 错误处理
- 服务关闭

---

## 10. 注释

注释应该解释“为什么”。

不要写无意义的：

// 获取用户
func GetUser()

复杂安全逻辑必须增加必要注释。
